# ZelenkaMusic

## Актуальные файлы установки находятся в релизах
[![ТУТ](https://img.shields.io/github/v/release/shakinessaim/zelenkamusic)](https://github.com/shakinessaim/zelenkamusic/releases/latest)

## ВНИЗУ КАК СОБРАТЬ И ГАЙДЫ И Т Д И ТП

Музыкальный проигрыватель для **Windows 10 и Windows 11** на Rust и Slint. Локальное воспроизведение MP3 и FLAC, альбомы, пользовательские плейлисты и необязательный снегопад. Основной цвет — **#7BCE9A**. Интерфейс и установщик на русском языке.

Дополнительная версия для **Android 8.0 и новее** находится в [`android`](android/README.md). Сборка APK: `powershell -ExecutionPolicy Bypass -File .\scripts\Build-Android.ps1`. Установщик создаётся в `dist\ZelenkaMusic-Android-0.1.3.apk`. Android-версия использует музыку из выбранной папки телефона, поддерживает альбомы, плейлисты, тексты песен и воспроизведение с выключенным экраном.

## Запуск

Запустите `ZelenkaMusic.exe` в папке проекта: рядом уже находится ваша папка `songs`. Установка для такого запуска не требуется.

В готовой версии папка `songs` всегда находится **рядом с исполняемым файлом**. Текущая рабочая папка на её выбор не влияет. Каждый альбом разместите в отдельном каталоге:

```text
songs/
  Название альбома/
    01 - Композиция.mp3
    02 - Композиция.flac
    cover.jpg
```

После добавления музыки нажмите **Обновить** в медиатеке. Метаданные и встроенные обложки читаются автоматически. Если встроенной обложки нет, приложение ищет JPG, JPEG, PNG или WebP в каталоге альбома. Для файлов без обложки используется логотип из `newlogo.jpg`.

## Управление

- **Главная:** большая кнопка запускает случайную композицию или приостанавливает/продолжает воспроизведение. Каждая композиция проигрывается один раз за цикл; соседние циклы не повторяют последнюю композицию подряд.
- **Медиатека:** вкладки **Альбомы** и **Плейлисты**. Откройте карточку, нажмите **Слушать** для воспроизведения по порядку или **Перемешать** для случайного порядка.
- **Плейлисты:** создавайте, переименовывайте и удаляйте подборки. Кнопка **+** рядом с композицией добавляет её в выбранный плейлист. Корзина рядом с композицией удаляет её из плейлиста; музыкальный файл остаётся на месте.
- **Проигрыватель:** предыдущая/следующая композиция, пауза, громкость, перемешивание и повтор. Перемотка выполняется при отпускании ползунка; во время перетаскивания он показывает выбранную позицию. Громкость меняется непрерывно.
- **Повтор:** выключен → вся подборка → одна композиция (значок **1**). На главной случайный цикл продолжается и при выключенном повторе.
- **Настройки:** **Снегопад** включает 96 текстурных частиц. Они появляются в основной области, не перекрывая границы окна и нижних панелей.
- **Текст песни:** показывает вручную добавленный текст текущей композиции. Для `.lrc` отдельная строка следует за временем воспроизведения и перемоткой. Кнопка **Обновить** перечитывает файл после редактирования.

Воспроизведение продолжается при переходе между страницами. После перезапуска восстанавливаются композиция и её позиция, при этом воспроизведение остаётся на паузе. Предыдущая кнопка возвращает композицию в начало, если прошло более трёх секунд, иначе возвращает предыдущую из истории.

Плейлисты и настройки хранятся в `%LOCALAPPDATA%\ZelenkaMusic\zelenka.db`. Кэш обложек находится в соседней папке `artwork`, отчёт об ошибках сканирования — в `library-report.txt`. Музыкальные файлы приложение не изменяет. Если временно отсутствующая композиция вернётся по прежнему пути, её связь с плейлистом восстановится.

## Тексты песен и загрузка музыки

Папка `lyrics` располагается рядом с `songs`. Добавляйте обычные тексты в UTF-8 `.txt` или синхронизированные `.lrc` (также поддерживается UTF-16 с BOM). Используйте имя аудиофайла, заменив расширение:

```text
songs/Альбом/01 - Композиция.flac
lyrics/Альбом/01 - Композиция.txt
```

Также можно размещать файлы непосредственно в `lyrics`. Файл из соответствующей папки альбома имеет приоритет; в одной папке `.lrc` имеет приоритет над `.txt`. Пример LRC: `[00:12.50]Строка песни`. Поддерживаются несколько временных меток, метаданные и `[offset:500]` (положительное значение показывает строки раньше). Максимальный размер текста — 1 МБ. Подробнее: [`lyrics/README.md`](lyrics/README.md).

Windows-установщик предлагает необязательную загрузку папок `songs` и `lyrics` из [shakinessaim/zelenkamusic](https://github.com/shakinessaim/zelenkamusic). В Android откройте **Настройки**, выберите отдельные папки для музыки и текстов с доступом для записи, затем нажмите **Скачать музыку и тексты**. Загрузка продолжается с уведомлением, её можно остановить. После завершения или отмены медиатека обновляется при открытии приложения.

Для скачивания репозиторий должен быть публичным. Загружаются только эти две папки с сохранением структуры; уже существующие файлы пропускаются. Повторная загрузка продолжает добавление недостающих файлов. Незавершённый файл удаляется; готовые остаются. Поддерживаются обычные файлы Git и публичные файлы Git LFS. Воспроизведение и показ текстов работают без интернета.

## Сборка

Установите [Rust](https://rustup.rs/) версии 1.89 или новее с инструментарием MSVC и [Visual Studio Build Tools](https://visualstudio.microsoft.com/downloads/) с компонентами **Разработка классических приложений на C++** и **Windows SDK**. Для первого скачивания зависимостей нужен интернет.

```powershell
cargo run --bin zelenka-music
```

Отладочные сборки используют `songs` в папке исходного проекта. Для готовой версии используется папка рядом с EXE.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Build.ps1 -Installer
```

Результаты:

- `ZelenkaMusic.exe` — приложение рядом с существующей библиотекой.
- `dist\ZelenkaMusic\ZelenkaMusic.exe` — переносимая версия с пустой папкой `songs`.
- `dist\ZelenkaMusic-Windows-x64.zip` — архив переносимой версии.
- `dist\ZelenkaMusic-Setup-0.1.3.exe` — установщик.

При наличии [Inno Setup 6](https://jrsoftware.org/isinfo.php) сборка использует его; иначе установщик собирается компилятором .NET Framework, входящим в Windows. Сам проигрыватель написан на Rust. Логотип приложения и значок Windows создаются из `assets\images\logo.jpg`, скопированного из `newlogo.jpg`.

Установщик размещает приложение в `%LOCALAPPDATA%\Programs\ZelenkaMusic`, создаёт ярлыки приложения, музыки и текстов в меню «Пуск» и регистрирует удаление в настройках Windows. Для установленной версии поместите альбомы в её папку `songs` или выберите загрузку с GitHub при установке. Ошибка загрузки не мешает пользоваться установленным проигрывателем; повторите установку для скачивания оставшихся файлов. Удаление сохраняет музыку, тексты и пользовательские данные.

## Проверки

```powershell
cargo check --all-targets
cargo clippy --all-targets -- -D warnings
cargo test --lib
cargo test --test window_restore -- --nocapture
cargo test --bin zelenka-music pointer_sliders_and_incremental_snow -- --nocapture
cargo test --bin zelenka-music real_ui_and_audio_smoke -- --ignored --nocapture
cargo run --bin verify-library -- .\songs
```

Проверка `pointer_sliders_and_incremental_snow` отправляет события мыши, проверяет клики и длинные перетаскивания, изменение размера окна, а также последовательную отрисовку со снегом в одном и двух буферах на всех трёх страницах. Результат сравнивается с полной отрисовкой, чтобы выявлять повреждённые края и следы частиц.

В версии 0.1.2 исправлен вывод сохранённого изображения после восстановления окна Windows: при запросе перерисовки вся клиентская поверхность копируется из буфера, включая неподвижные края. Частичная отрисовка внутри буфера сохранена. Локальное исправление Slint находится в `vendor\i-slint-backend-winit`; его назначение описано в `vendor\README.md`.

Тесты `window_restore` проверяют восстановление потерянной поверхности со снегом и без него в трёх размерах окна, а также реальное копирование пикселей через Win32 GDI. Потеря поверхности в этих тестах моделируется; видимое сворачивание и восстановление окна они не проверяют.

Проверка `real_ui_and_audio_smoke` требует вашей папки `songs` и доступного аудиоустройства Windows. Она использует настоящий CPAL-выход при нулевой громкости, проверяет MP3/FLAC, ползунки, паузу, перемотку, переходы в конце композиции, плейлисты, ошибки ввода и сохранение снега. Снимки страниц записываются в `target\verification`. Рабочая пользовательская база при тестах не изменяется.

## Устройство проекта

- `src/audio`: потоковый декодер Symphonia, ресемплинг, вывод CPAL и очередь воспроизведения. Ограниченный буфер вмещает полсекунды звука; аудиоколбэк не читает диск, не декодирует и не использует блокировки.
- `src/library`: фоновое сканирование, Lofty, извлечение обложек. Неизменённые файлы используют сохранённые метаданные; для списков подготовлены маленькие обложки размером 80 пикселей.
- `src/database`, `src/playlists`, `src/settings`: SQLite с внешними ключами и WAL. В базе находятся пути, метаданные, связи плейлистов и настройки, без аудиоданных.
- `src/app.rs`: соединение интерфейса с сервисами, состояние воспроизведения, сообщения и сохранение.
- `ui`: страницы, повторно используемые элементы управления, нижний проигрыватель, навигация и снегопад.

Windows-версия использует аудиоустройство Windows по умолчанию. После его отключения приложение показывает сообщение; подключите устройство и перезапустите проигрыватель. Дополнительная Android-версия реализована отдельно в `android`; музыка и настройки между устройствами автоматически не синхронизируются.
